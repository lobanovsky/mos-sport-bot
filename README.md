# Московский Спорт официальный бот

Телеграм-бот `@mos_sport_bot`. Каждый пользователь может подписаться на
любую страницу вида `https://sport.mos.ru/sections/<id>` и получать
уведомление, когда там появляется запись.

Бот намеренно «глупый»: вся логика (какие URL мониторить, кто на что
подписан, лимиты) живёт на `mos-sport-backend`. Бот — тонкий прокси:
Telegram-команды превращает в HTTP-вызовы к бэкенду, а входящий пуш от
бэкенда (когда запись появилась) — в сообщения конкретным чатам, которые
бэкенд сам указывает в `chat_ids`.

Бот и бэкенд разворачиваются на разных серверах, поэтому общаются по
публичному адресу и порту, а не через docker-сеть: бэкенд стучится в
`http://<адрес бота>:8088/webhook/notify`, а бот — в
`http://<адрес бэкенда>:<порт>/subscriptions`, `/status` и т.д. Порты на
обоих серверах должны быть открыты во внешнем файрволе отдельно — самим
Docker Compose это не делается.

## Команды бота

- `/subscribe <url>` — подписаться на URL (только `https://sport.mos.ru/...`).
- `/unsubscribe <url>` — отписаться от URL.
- `/list` — показать список URL, на которые подписан текущий чат.
- `/status` — показать состояние мониторинга по всем подпискам текущего чата.

## Запуск

```sh
cp .env.example .env
go run ./cmd/bot
```

Или через Docker Compose:

```sh
cp .env.example .env
docker compose up --build
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота из BotFather. Обязательна. | — |
| `WEBHOOK_SECRET` | Общий секрет с бэкендом: им подписаны входящие вызовы `/webhook/notify` от бэкенда и исходящие вызовы бота к API бэкенда. Обязательна. | — |
| `LISTEN_ADDR` | Адрес HTTP-сервера бота. | `:8088` |
| `BACKEND_API_URL` | Публичный базовый URL HTTP API бэкенда (`/subscriptions`, `/status`). Обязательна — без бэкенда бот бесполезен. | — |
| `REQUEST_TIMEOUT` | Таймаут запроса к бэкенду. | `10s` |

## HTTP API бота

### `GET /healthz`

Проверка, что HTTP-сервер запущен. Ответ `200 ok\n`.

### `POST /webhook/notify`

Вызывается бэкендом при появлении записи на конкретном URL. Требует заголовок
`X-Webhook-Secret` со значением `WEBHOOK_SECRET`.

Тело запроса:

```json
{
  "available": true,
  "checked_at": "2026-08-25T07:26:03.221219Z",
  "url": "https://sport.mos.ru/sections/11716",
  "active_buttons": 1,
  "buttons": ["Записаться"],
  "chat_ids": [123456789, 987654321]
}
```

Бот рассылает уведомление только тем `chat_ids`, что указал бэкенд — сам
список подписчиков он не хранит.

Ответы:

- `200 {"sent":N,"failed":M}` — уведомление разослано.
- `204` — `available:false` или пустой `chat_ids` — рассылки не было.
- `400` — тело запроса не разобрать как JSON.
- `401` — неверный или отсутствующий `X-Webhook-Secret`.

## Деплой

CI/CD — GitHub Actions (`.github/workflows/build-and-deploy-bot.yml`), по
образцу `mos-sport-backend`: тесты → сборка и публикация Docker-образа →
деплой по SSH с healthcheck и автооткатом.

Для работы пайплайна в репозитории на GitHub нужно завести секреты:

- `DOCKER_USERNAME`, `DOCKER_TOKEN` — доступ к Docker Hub.
- `DEPLOY_HOST_IP`, `DEPLOY_HOST_USERNAME`, `DEPLOY_HOST_KEY` — SSH-доступ к
  серверу (`qlibin_server`).
- `DEPLOY_HOST_PROJECT_PATH` — `/home/evgeny/projects/mos-sport-bot`.
- `TELEGRAM_BOT_TOKEN` — токен бота.
- `WEBHOOK_SECRET` — общий секрет с бэкендом (сгенерировать, например,
  `openssl rand -hex 32`, и прописать то же значение в `BOT_WEBHOOK_SECRET`
  бэкенда на сервере).
- `BACKEND_API_URL` — публичный адрес HTTP API бэкенда, например
  `http://<ip бэкенда>:8082`. **Без открытого наружу порта бэкенда команды
  `/subscribe`, `/unsubscribe`, `/list`, `/status` работать не будут** —
  это отдельная настройка файрвола на сервере бэкенда, вне кода этого репозитория.

Порт `8088` должен быть открыт на сервере деплоя (внешний файрвол/security
group) — иначе бэкенд не сможет достучаться до `/webhook/notify`.
